## Defect and changes

- The old main loop called save_world() every >20 accumulated frame seconds, ignored its return value, then reset save_timer even on failed writes. This allowed unbounded unsaved progress. Normal close also ignored write failure.
- world_model.gd: last_checkpoint_clock is a transient watermark for the last successfully loaded/written snapshot; checkpoint_if_due() uses the authoritative simulation clock and exact >=20.0 boundary. A successful explicit save advances the watermark too. A failed write latches CHECKPOINT_WRITE_FAILED via the existing recovery guard, preserves last valid generation/backup and denies further snapshot or object event mutations until a new load. Existing scratch validation and safe rotation retained. Twenty simulation seconds is an engineering choice, not an owner-mandated number.
- main.gd: no independent frame save timer; check the checkpoint result before the next rendered update. Stop processing/input and show the existing recovery screen on failure. Explicit close handling disables automatic acceptance of the close request; failed close checkpoint surfaces recovery instead of reporting normal success. life.gd tick returns immediately if recovery is blocked. Mid-tick failure can still leave transient mutations during that tick; do not claim transactionality of all activity state.
- No layout, clock-rate, activity-duration, asset or private data changes.

## Remaining A18/A19 risk

The durable object event may have a simulation timestamp newer than the restored snapshot clock (fixture explicitly proves 59.875 vs restored 40/20). Do not blindly advance the entire world clock to the event watermark: this would age unrelated commitments without restored actor state. Need a coherent cross-store recovery contract with time/provenance, including reconstructed journal timestamps (currently uses restored world clock), exact-once VIEW_ART completion/learned-habit credit across a crash, and explicit handling of post-checkpoint durable object events in changed topology/permission/actor state. Also persist/reconcile RNG and full-world activity, media, group, lift and other state where necessary; no claim of complete event sourcing. Next targeted regression should reproduce object view completion committed before the actor snapshot and prevent duplicate completion/credit; then broader combined-state crash tests.
